# Atlas HUD (frontend/index.html)

Mode: Operate. Audience: the owner, daily, desktop, dim room. Job: chat with a local model and see which Atlas modules exist yet.

## Direction contract

THESIS: Atlas's chat lives inside a holographic HUD whose core is the model itself: the core's rings spin at the measured stream rate and the module ring around it lights up only for backend routes that really exist. Refuses the category default of a sidebar + centred transcript chat clone.

OWN-WORLD: Blue-black projection ground with a faint grid; cyan ink (#d8f6ff body, #3ad8ff signal, near-white core), amber for stubs/warnings, red for failure. Saira variable: expanded width, tracked caps for panel heads and readouts; normal width for reading. Panels are 1px cyan frames with corner brackets; glow only on the core, clock and live values.

STORY: The owner sees the link is up, which model answers, and what he has built. He types; the reply streams into the log while the core reacts; he reads it comfortably.

FIRST VIEWPORT: Top bar (wordmark, link/model status, operator, clock). Left rail: Link latency history, Stream readouts, Session, Hardware (awaiting /api/system). Centre: the core (~55% of viewport height) with ten module nodes on its ring and horizontal beams. Right: Session log transcript with the composer at its foot (primary action). Bottom strip: traffic, Atlas plate, reboot.

FORM: Pinned by the owner (JARVIS reference image); position 1 of 1. seed: none (roll skipped: direction pinned by the owner, in his words: "I want it to look like Jarvis from IRON MAN. I gave you an image"). Signature interaction: the core couples to the stream (thinking sweep, chunk pulses, rotation speed from chunks/s) and a pulse travels the beam from core to log.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
